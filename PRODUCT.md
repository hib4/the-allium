# The Allium

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

React, TypeScript, Vite; PixiJS WebGL rendering with a shared-choreography animated Canvas 2D fallback.

## Users

Deaf and hard-of-hearing concert audiences at Glitz Inclusive, Jakarta; visual operators; optional mobile companions.

## Product Purpose

Translate musical rhythm, pitch, intensity and expression into an identifiable shared visual score with captions.

## Operating Context

1920×1080 projection and panoramic 5:1 LED concert display; same-browser operator and display tabs; independent mobile visual-only demo. Performance must not require public internet.

## Capabilities and Constraints

Five routes, six instrument languages, scene focus modes, standalone Demo, Ui24R Live audio analysis through a local input-only Python/WebSocket service, configurable grouped USB channels, graceful Standby, and manual captions. macOS CoreAudio and Windows ASIO support require physical rehearsal verification. No source separation, recording, automatic transcription, venue relay or cross-device control sync. USB channel references never define venue instrument assignments.

## Brand Commitments

The Allium; warm, artistic, inclusive, editorial. Supplied navy, blue, teal, pink, violet and yellow palette. Living musical lines, not an equalizer or dashboard. Original logo unavailable: use temporary text identity and reserve logo placement.

## Evidence on Hand

User-provided brief and example copy; no original logo, event dates, artist lineup or testimonials supplied. Demo lyrics are sample content.

## Product Principles

Music determines motion. Instrument identity survives grayscale. Captions remain readable. Controls report truthful state.

## Accessibility & Inclusion

WCAG 2.2 principles; keyboard access, reduced motion, high contrast, no rapid full-screen flashes.

## Internal release candidate

Portable runtime packaging, operator Start Live/Stop visualization, export/restore settings, diagnostic export and Indonesian on-site guidance extend the existing interface. English UI and audience visual identity remain unchanged. macOS ARM64 has a local build; Windows build tooling requires native validation. Actual mixer and venue acceptance remain separate gates.
